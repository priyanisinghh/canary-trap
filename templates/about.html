About CanaryTrap

What is a Canary Token?

Miners once carried canary birds underground. If the bird stopped singing, danger was near. A canary token works the same way: it is a file that nobody should ever open. If someone does, CanaryTrap knows right away.

How the project works

  1. You enter a file name, the folder to protect and a file type.
  2. The server creates a unique random token ID (a UUID) and stores it in an SQLite database.
  3. You download the token file and place it in the folder you want to monitor.
  4. The file contains a small hidden link back to CanaryTrap. When someone opens the file, their device requests that link.
  5. CanaryTrap records the date, time, IP address and browser, shows an alert, and updates the folder's risk percentage.

Folder risk percentage

The risk is built from three parts: up to 60 points for the share of tokens opened by someone else, 10 points for each other-user open (up to 30), and 10 points if an other-user open happened in the last 24 hours. Opens from devices you marked as yours are ignored.

Example: one token in a folder, opened by another user a few minutes ago: 60 + 10 + 10 = 80% (Critical).

ScoreLevelMeaning
0 – 19%LowNo suspicious opens
20 – 49%MediumSome opens by others, but not recent
50 – 79%HighSeveral opens by others, or recent activity
80 – 100%CriticalRecent, repeated access by someone else. Investigate now.

Technology used

Frontend: HTML, CSS and JavaScript · Backend: Python with Flask · Database: SQLite · Token IDs: Python's uuid module (cryptographically random)

Limitations (honest notes)

This is a student prototype. It has no login system. "Your device" is recognized by IP address and browser, so another person using the same browser on the same network could be treated as you. Antivirus or file-preview tools can also open files and create false alerts.
